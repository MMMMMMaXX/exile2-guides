# 静态预渲染

> 本节更新时间：2026-07-26 22:03（Asia/Shanghai）

## 构建契约

`react-router.config.ts` 在每次生产构建时读取内容索引，并把以下路径交给 React
Router 的 `prerender`：

- 已注册的固定公共路径；
- 所有通过 Schema 和索引校验的 `published` 内容详情路径。

草稿、缺少人工核验信息的样例和无效内容会在进入路径清单前被排除或令构建失败。
正文在构建阶段读取并渲染，浏览器不会再请求 Markdown/MDX 源文件。

## 产物门禁

构建结束后会逐个读取公共路径对应的独立 `index.html`，并验证：

1. 文件存在；
2. `<title>` 非空；
3. `<meta name="description">` 非空；
4. 普通页面包含服务端生成的 `<main>`；
5. 内容页包含构建期正文标记。

任何一项不满足都会令生产构建失败，避免空壳页面被部署。

## React Router 8 兼容边界

当前 React Router 8 在 `ssr:false` 且启用预渲染时禁止路由导出服务端
`loader`。项目不能为了读取文件内容而切换成依赖运行时服务器的 SSR，因此由 Vite
插件在构建期生成 `virtual:content-pages`：

- 文件系统、Front Matter 和 MDX 编译依赖只在构建端运行；
- 浏览器路由只读取生成后的已发布页面数据；
- 正文直接写入各 URL 的 HTML，不进行客户端 Markdown 请求；
- 路由模块不导入 Node 文件系统代码。

这是对当前官方 API 的适配，不改变 PRD 的静态预渲染与无后端原则。

## 扩展规则

后续任务注册新的首页、列表页、搜索页或法律页时，必须同步将固定路径加入
`fixedPublicPaths`。内容详情路径只允许从生产内容索引派生，不得手写样例路径。
