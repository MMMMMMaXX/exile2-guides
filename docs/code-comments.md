# 中文代码注释规范

> 本节更新时间：2026-07-26 15:22（Asia/Shanghai）

## 文件级注释

所有人工维护且语法支持注释的源码、配置、脚本、测试和 Markdown 文档必须以中文
文件级注释开头，说明：

- 文件负责什么。
- 哪些职责不属于该文件。
- 修改时需要保持的关键边界。

严格 JSON、锁文件、生成物、二进制资产、`.nvmrc` 和作为唯一事实源的
`EXILE2-GUIDES-PRD.md` 不加入注释。

## 函数注释

所有具名函数必须在定义前具有中文 TSDoc、JSDoc 或普通注释。注释重点说明用途、
输入输出、关键不变量或扩展边界，不逐句翻译函数实现。

匿名回调只在承载重要规则时增加说明；简单的映射、断言和事件转发不强制逐个注释，
避免低价值注释掩盖核心逻辑。

## 自动检查

运行：

```bash
npm run check:comments
```

检查器验证：

1. 纳入范围的文件顶部存在中文职责注释。
2. TypeScript/JavaScript 具名函数定义前存在中文注释。

新增源码目录或配置文件时，需要同步扩展
`scripts/check-comments.ts` 的扫描范围，并更新本节时间。
